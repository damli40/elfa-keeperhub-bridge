Agent Economy · main track

Elfa decides when. KeeperHub decides how.

Elfa Auto watches markets and fires when a condition comes true. It used to place the order too. It doesn’t any more, so every user who wants a condition to actually move money has to build the riskiest part themselves.

The problem

Elfa’s documentation now tells users to route follow-up execution through their own runner. That runner is exactly the component that fires twice when a webhook is retried, executes on a forged request because nobody checked the signature, or moves the wrong amount because a number arrived in the wrong unit.

KeeperHub already does execution properly: hosted wallet, spending caps, a log of every step. It even accepts an incoming webhook. But that webhook requires an Authorization: Bearer header, and Elfa’s webhook action sends only its own signature headers with no way to add one.

The two products cannot talk to each other. That gap is the reason this exists.

The shape

What it refuses

The rubric asks whether a build survives conditions outside the happy path. The bridge applies each gate in order. Authenticated refusals create a log row; malformed and forged requests create none.

The one idea that matters

No amount, token, chain or address ever comes from the message. They live in the KeeperHub workflow, fixed. The message may only say that the condition fired. It cannot influence how much moves, or where it goes.

A test scans every field of the workflow definition to prove no money value reads from the incoming payload. That guard is why the adversarial review on 9 September mattered: the tests protecting those values were not pinning them. Halving the swap amount passed 27 of 27. Redirecting the payout to a 0xDEADBEEF address passed 36 of 36. Both fail now, each verified by breaking it on purpose and watching the suite go red.
